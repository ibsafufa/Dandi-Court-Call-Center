# Phone & Computer Calling System

A simple two-person voice/video calling website. It works in a modern browser on Android/iPhone and on Windows/macOS/Linux computers. It uses WebRTC for media and Socket.IO for call signaling.

## Requirements

- Node.js 18 or newer
- A computer/server that can run Node.js and be reached by both participants
- HTTPS for public use (camera and microphone permissions are restricted to secure contexts; `localhost` is allowed for local testing)
- For reliable calls across different networks, configure a TURN server (instructions below)

## Run locally

1. Install Node.js 18+.
2. Extract this project and open a terminal in its folder.
3. Install dependencies:

   ```bash
   npm install
   ```

4. Start the server:

   ```bash
   npm start
   ```

5. On the same computer, open `http://localhost:3000`.
6. For a second device on the same Wi-Fi, open `http://COMPUTER-LAN-IP:3000`. Find the computer's LAN IP using `ipconfig` on Windows or `ip addr` on Linux/macOS network settings.

**Important:** On phones, `http://192.168.x.x` is generally not treated as a secure context for camera/microphone access. Use HTTPS for phone testing, or use localhost on the phone only for local development.

## Use the calling app

1. On the first device, enter your name and generate a room code.
2. Select **Copy invitation link** and send it to the other participant.
3. On the second device, open the link, allow camera/microphone access, and join.
4. Both participants should now see and hear each other.
5. Use the buttons to mute the microphone, turn the camera off, share the screen, or leave.

Only two participants are allowed in each room in this starter version.

## Deploy for internet access

You need to deploy the Node.js server to a host that supports long-running Node.js apps and WebSocket connections. GitHub Pages alone cannot run this signaling server.

1. Upload the project to a Git repository.
2. Deploy it to a Node.js hosting provider that supports WebSockets.
3. Set the host's start command to `npm start`.
4. Enable HTTPS on the hosting domain.
5. Open the HTTPS site on both devices and share the room invitation link.

The frontend and signaling server are served by the same Node.js app. If you host the frontend separately, update the Socket.IO connection URL in `public/app.js` and configure the server's allowed origin.

## TURN server (recommended for production)

The included Google STUN server helps devices discover their public network addresses. Some mobile carriers, office networks, and strict firewalls block direct peer-to-peer media. For dependable internet calling, use a TURN relay server (for example, coturn on a VPS with the required UDP/TCP ports open).

After setting up TURN, add its details to `rtcConfig.iceServers` in `public/app.js`:

```js
{
  urls: "turn:YOUR_TURN_DOMAIN:3478",
  username: "TURN_USERNAME",
  credential: "TURN_PASSWORD"
}
```

For production, use time-limited TURN credentials generated by your backend rather than hard-coding permanent credentials in browser JavaScript.

## Security and limitations

- This is a starter implementation for a two-person call, not a complete enterprise telephony platform.
- Use HTTPS, keep Node.js dependencies updated, and restrict who can create/use rooms before using it for sensitive court or legal conversations.
- Room codes are not authentication. Anyone with the invitation link may try to join an available room.
- Add user authentication, access logs, rate limiting, room expiry, and secure TURN credential issuance before handling confidential calls.
- The app does not call ordinary telephone numbers or connect to the cellular voice network. It makes internet-based browser calls.
- Browser permissions are required for microphone, camera, and screen sharing.
- GitHub Pages is static hosting and cannot run this Socket.IO signaling server by itself.
